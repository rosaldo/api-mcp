# Changelog

> Generated from `git` by `scripts/gen-changelog.sh` — do not edit by hand.

- **v1.9.1** (2026-08-29) · `fix` — the server now announces the file prefix in its instructions, because a capability the model is not told about does not exist: --blob-in was configured, the process was running with it, and the model still sent a bare path and got it rejected by the API — nothing in the schema, the tool description or anywhere else said the prefix was there to be used, and no schema can say it since it applies to every string argument; the notice names the directory too, and stays EMPTY when the flag is off, because announcing a prefix that would be passed through untouched is worse than silence
- **v1.9.0** (2026-08-29) · `feat` — a path can now stand where the bytes go, which is the only way a model attaches a file it cannot carry: the asymmetry that made --blob-dir necessary runs the other way too, because attaching a 185 KB PDF to a Gmail message means producing the entire RFC 2822 message base64d AS AN ARGUMENT — a quarter of a megabyte the model has to hold and type out, and measured in the field the same send went through with a small attachment and was impossible with the real one; --blob-in names a directory, an argument starting with file: is read from it and base64d on the way to the API, and the model never sees the payload; reading is confined to that directory RESOLVED, since .. and a symlink pointing outside are exactly how a contained path stops being one, and the alphabet follows the dialect because Google declares its format byte fields as base64URL while OpenAPIs is plain base64
- **v1.8.2** (2026-08-26) · `chore` — the flag table is now checked against the real flag set, in both directions: a flag added without documenting it fails the build, and so does a documented flag that no longer exists — the section was called All flags while listing barely half of them
- **v1.8.1** (2026-08-26) · `docs` — the flag table and the architecture map catch up with what the tool actually does: --type still offered two dialects out of three, --depth was documented under its old GraphQL-only name, and --blob-dir was not there at all
- **v1.8.0** (2026-08-26) · `feat` — Google's discovery document becomes a dialect: they publish one for over three hundred of their APIs at a predictable address and no OpenAPI parser reads it, so writing this reader once makes Drive, Sheets, Calendar, Gmail and the rest reachable without a line of code per API
- **v1.7.0** (2026-08-26) · `feat` — responses can hand the model a file path instead of a megabyte of base64: an inlined image arrives as 1.17 MB in a single field, which is a third of a million tokens the model can neither look at nor save, so --blob-dir writes those bytes to disk and leaves the shape of the answer intact
- **v1.6.0** (2026-08-26) · `feat` — the server now tells the client what it is for, taken from the spec's own info: under tool search a client loads only tool names and the server instructions up front, so a server that says nothing about itself is one the model never searches
- **v1.5.0** (2026-08-23) · `refactor` — releases move to CI: pushing a tag now builds and publishes, and push.sh only ships commits and tag unless --full is given — Actions is free on public repositories, so the published binaries stop depending on whichever toolchain this workstation happens to have
- **v1.4.0** (2026-08-22) · `feat` — sign gains method, base64 and iso8601 timestamps: a scheme that signs the verb, encodes base64 and stamps an ISO instant had no way to be expressed — and every one of those mismatches fails as an authentication error that never names the format
